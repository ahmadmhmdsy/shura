- **التاريخ:** 2026-09-05

## 1. الملخص التنفيذي

«شورى» تطبيق دردشة محلي مع نماذج الذكاء الاصطناعي، يميّزه **الإرسال المتوازي**: سؤال واحد يُوجَّه في نفس اللحظة إلى عدة مزودين/نماذج تختارهم، فتظهر النتائج في بطاقات مستقلة قابلة للمقارنة. التطبيق يتواصل مباشرة من جهاز المستخدم إلى المزودين بمفاتيح API خاصة بهم — **لا باك-إند ولا خادم وسيط إطلاقًا**. الجلسات تُحفظ مرتين: قاعدة بيانات محلية (سريعة، للفهرسة والداشبورد) + مجلدات Markdown على القرص (دائمة، مقروءة بالبشر، قابلة للاسترجاع والتصدير).

## 2. الأهداف وغير الأهداف

### أهداف MVP (المرحلتان 0 + 1)
1. إدارة المزودين الأربعة ومفاتيحهم محليًا من داخل التطبيق.
2. جلسات دردشة محفوظة تلقائيًا (قاعدة بيانات + ملفات Markdown).
3. الإرسال المتوازي بوضعيه: سؤال موحّد للجميع، أو سؤال مخصص لكل نموذج (مع قاعدة توريث ثلاثية).
4. بث مباشر (Streaming) للنتائج في بطاقات لكل مزود، مع تبديل عمودي/أفقي.
5. مؤشر استهلاك الكونتيكست داخل مربع الإدخال + عدّاد توكنز/تكلفة لكل بطاقة.
6. زر «استخرج خلاصة» يرسل نتائج آخر تمرّة إلى النموذج الأساسي للجلسة.
7. استرجاع الجلسات من المجلدات عند فقدان القاعدة.

### خارج نطاق MVP (مراحل لاحقة معتمدة)
- **المرحلة 2+:** تصدير شامل/أرشيف ZIP، إعادة استيراد انتقائي.
- **المرحلة 3:** الداشبورد الكامل (تحليلات الاستهلاك والتكلفة والكاش والأدوات).
- **المرحلة 4:** المنسّق الذكي (النموذج الأساسي يستجوب نماذج معزولة عبر أداة ويستخلص).
- **المرحلة 5:** إدخال الصوت، ومرفقات الصور/الملفات حيث يدعمها الموديل.

### غير أهداف (Non-Goals)
- أي خادم أو خدمة سحابية تابعة لنا. أي اشتراك أو دفع داخل التطبيق. أي تتبع/إحصاءات خارجية. مشاركة الجلسات سحابيًا.

## 4. المعمارية

### 4.1 الحزمة التقنية
- **Vite + React + TypeScript (strict)** — واجهة سريعة وأخطاء مبكرة.
- **Tailwind CSS + shadcn/ui + متغيرات CSS مركزية** — ثيم قابل للتغيير من طبقة Tokens.
- **Vercel AI SDK** (المكتبة الموحّدة): `@ai-sdk/openrouter`، `@ai-sdk/google`، `@ai-sdk/openai-compatible` (لـ MiniMax وOpenCode Go). إضافة مزود جديد = سطر تكوين في السجل، لا ملف معمار جديد.
- **Zustand** للحالة (مخزن لكل مجال: sessions/settings/usage/composer).
- **Dexie (IndexedDB)** لقاعدة البيانات المحلية.
- **Tauri 2** للغلاف الأصلي مع الإضافات: `http` (نقل بلا CORS)، `fs`، `dialog`، `opener`. صلاحيات محصورة بنطاقات المزودين + مجلد الجلسات فقط.

### 4.2 الوحدات السبع (مسؤولية واحدة لكل وحدة)
```
UI (React/shadcn) ← State (Zustand) ← منطق الجلسة/الإرسال
      ↓                                      ↓
Persistence (Dexie + كاتب Markdown) ← Provider Registry (AI SDK) ← Transport (fetch / tauri-http)
                                                                ↓
                                                      Analytics (usage_events → الداشبورد)
```

### 4.3 طبقة النقل (حاسمة لـ OpenCode Go)
نتائج فحص CORS الفعلي (2026-09-05):
| المزود | نداء المتصفح المباشر |
|---|---|
| OpenRouter `https://openrouter.ai/api/v1` | ✅ مفتوح (Access-Control-Allow-Origin: *) |
| Gemini `https://generativelanguage.googleapis.com` | ✅ مفتوح |
| MiniMax `https://api.minimax.io` | ✅ مفتوح (يُعاد التحقق بنداء فعلي في المرحلة 0) |
| OpenCode Go `https://opencode.ai/zen/go/v1` | ❌ محجوب (OPTIONS: 404 بلا ترويسات CORS؛ POST: 401 بلا ترويسات) |

**القاعدة:** طبقة `Transport` واحدة بواجهة موحدة؛ داخل المتصفح تستخدم `fetch`، وداخل Tauri تستخدم إضافة `http` الأصلية (بلا قيود CORS). في وضع الويب الخالص، المزودون المحجوبون يظهرون بحالة «يتطلب تطبيق سطح المكتب» بدل فشل صامت.

### 4.4 سجل المزودين (Provider Registry)
لكل مزود كائن تكوين واحد: `id, label, transport, baseURL, authHeader, modelsSource, pricing`.
- **OpenRouter:** قائمة الموديلات والأسعار تُجلب حيًّا من `GET /api/v1/models` (تشمل pricing) مع كاش.
- **Gemini:** `@ai-sdk/google`؛ قائمة الموديلات من ListModels مع قائمة احتياطية ثابتة.
- **MiniMax (intl):** `@ai-sdk/openai-compatible` على `https://api.minimax.io/v1`؛ قائمة ثابتة قابلة للتحديث.
- **OpenCode Go:** `@ai-sdk/openai-compatible` على `https://opencode.ai/zen/go/v1/chat/completions` (وموديلات مختارة عبر `/v1/responses`) — مع ترويسة `x-opencode-session` (ID جلسة ثابت لكل جلسة دردشة) وUser-Agent مميز باسم التطبيق (شرط البوابة). قائمة الموديلات من وثائقهم، قابلة للتحديث.

## 5. نموذج البيانات (Dexie)

| الجدول | الحقول |
|---|---|
| `sessions` | id، title، createdAt، updatedAt، modelIds[]، primaryModelId، layoutMode، onDisk (bool) |
| `messages` | id، sessionId، turnId، role، kind (user/assistant/synthesis)، text، attachments?، providerId?، modelId?، promptKind (shared/custom)، usage?، status، createdAt |
| `usage_events` | id، sessionId، turnId، providerId، modelId، inputTokens، outputTokens، cachedTokens، costUSD، toolCalls، durationMs، status، ts |
| `settings` | مفتاح/قيمة: providerKeys، primaryModel، paths، theme، timeouts، pricingOverrides |

### شكل التمرّة الموازية (Turn)
```
turn = { id, sharedPrompt?, customs: {modelId → نص?}, results: [{providerId, modelId, text, usage, status}] × N }
```

## 6. الحفظ الدائم

```
Documents\Shura\sessions\
└── <YYYY-MM-DD>_<عنوان-مبسط>_<id8>\
    ├── session.md            ← الجلسة كاملة (كل تمرّة: سؤالها + جواب كل مزود + جدول استهلاكه)
    ├── meta.json             ← بيانات وصفية + الاستهلاك (للاسترجاع)
    └── turns\t<NN>_<timestamp>\
        ├── 00_shared-prompt.md
        └── <NN>_<provider>__<model>.md   ← نتيجة كل مزود في ملف مستقل
```

**القواعد:**
- الكتابة بعد اكتمال كل تمرّة (وليس عند نهاية الجلسة)؛ فشل الكتابة ⇒ شارة «غير محفوظة على القرص» + زر إعادة محاولة، والقاعدة تبقى مصدر الحقيقة.
- الاسترجاع: عند الإقلاع، قاعدة فارغة + مجلدات موجودة ⇒ استيراد من `meta.json`.
- التصدير (MVP): جلسة = نسخ مجلدها لمكان يختاره المستخدم. (ZIP لاحقًا.)
- المفاتيح لا تُكتب في أي ملف Markdown إطلاقًا.

## 7. واجهة الدردشة

### 7.1 منطقة الإنشاء (Composer) — من الأسفل للأعلى
```
┌─ [⇄ عمودي/أفقي] ─────────────────────────── 📊 12% ─┐
│ شارات: [GPT ×][Gemini ×][MiniMax ×] [+ نموذج] [🔗 موحّد: مُفعّل] │
│ (وضع التركيز) حقل التركيز الكبير للنموذج النشط، والبقية شرائح مصغرة │
│ مربع الإدخال الأساسي (السؤال الموحد)                                │
│ 🎤 📎 🖼                              [إرسال] [⏹ إيقاف]            │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 قاعدة التوريث الثلاثية (منطق اختبارات إلزامي)
| السؤال الموحد | المخصص | ما يُرسل للموديل |
|---|---|---|
| ✓ | فارغ | الموحد فقط |
| ✓ | ✓ | الموحد ثم المخصص (يفصل بينهما فاصل، ويُعرضان منفصلين في البطاقة) |
| فارغ | ✓ | المخصص فقط (بلا موحد) |
| 🔗 مُفعّل | مخفي | الموحد للجميع حرفيًا |

### 7.3 التفاعلات
- **(+):** نافذة منبثقة: المزود ثم الموديل (قوائم حية حيث يدعم + احتياطية ثابتة).
- **وضع التركيز:** نقر شارة نموذج يكبّر حقل قريبًا من حجم المربع الأساسي ويصغّر البقية.
- **البطاقات:** بث حرفي، تذييل استهلاك (توكنز/تكلفة/كاش)، نسخ، إعادة توليد، إيقاف فردي، قسم «الجواب المخصص» قابل للطي (D4).
- **📊 مؤشر الكونتيكست:** تقدير توكنز الجلسة مقابل حد سياق الهدف المحدّد/المركّز فعليًا (من تعريف الموديل، لا من افتراض سجل المزودين) — أخضر/أصفر (80%)/أحمر (95%). التقدير تقريبي (chars/4) حتى يصل العدد الحقيقي من استجابة المزود. حين يكون الحد مجهولًا (بلا `contextLength`) يعرض المؤشر علامة جهل «؟» بدل نسبة مولّدة كاذبة.
- **السايدبار:** جلسات (بحث/إعادة تسمية/حذف بتأكيد)، جلسة جديدة، الإعدادات (مفاتيح، أساسي، مسارات، ثيم، مهلة افتراضية 120 ث).

### 7.4 الأدوار: النموذج الأساسي
- الأدوار العادية (بلا توازٍ) توجَّه للنموذج الأساسي بسياق الجلسة بحسب وضع السياق المختار (§7.5).
- زر «استخرج خلاصة»: يرسل للأساسي قالبًا يضم نتائج آخر تمرّة موازية ويستخرج خلاصة إجمالية (kind=synthesis).
- في المرحلة 4 يتوسع المنسّق ليستدعي نماذج معزولة عبر أداة (بلا أي سياق سابق إلا ما يحدده المستخدم/المنسّق).

### 7.5 وضع السياق (منفَّذ — المهمة 4)
- **الوضع لحاجة كل جلسة:** الافتراضي **stateful**؛ والانتقال إلى **«مقارنة stateless»** اختيار صريح يبديله المستخدم ويُثبَّت في سجل الجلسة — لا يوجد وضع stateless ضمنيًا أبدًا.
- **ماذا يُرسل:** رسائل كاملة (سؤال/جواب) من الأدوار المكتملة للجلسة نفسها فقط؛ تستبعد البادئات الجارية وصفوف الأخطاء والاستبدالات.
- **القصّ:** فوق الأدوار القديمة المكتملة أولاً حتى يبقى التقدير داخل ميزانية **80%** من حد سياق الموديل المستهدف. **السؤال الحالي لا يُسقط أبدًا** — وإن تتجاوز السؤال وحده الحد يفشل الإرسال قبل أي نداء للمزود.
- **حد السياق** يأتي من بيانات الهدف المحدّد/المركّز؛ موديل بلا حد يعرض علامة «؟» صادقة بدل نسبة مُفترضة.
- الوضع المختار يُثبَّت في `SessionMeta` في سجل الجلسة؛ أما لقطات إعادة المحاولة غير القابلة للتغيير وتنسيق العمليات فيبقى تنفيذهما من مهام المهمة 6.

## 8. الداشبورد (المرحلة 3)
- KPI: إجمالي Input/Output/المجموع، الكاش، التكلفة الكلية، عدد الرسائل، نداءات الأدوات.
- تفصيل حسب: المزود/الموديل/الفترة/الجلسة — من `usage_events` حصرًا.
- الأسعار: OpenRouter تلقائيًا من `/models`؛ البقية قيم افتراضية قابلة للتعديل في الإعدادات.
- الرسوم: Recharts (أعمدة للاستهلاك اليومي، خط للتكلفة).

## 9. معالجة الأخطاء
| الحالة | الاستجابة |
|---|---|
| 401/403 مفتاح | رسالة عربية في بطاقة المزود + رابط للإعدادات |
| 429 حد معدل | رسالة + إعادة محاولة يدوية (بلا إعادة تلقائية عدوانية) |
| انقطاع/مهلة 120 ث (قابلة للتعديل) | إيقاف النداء وحده؛ البقية تكمل |
| فشل كتابة القرص | شارة + إعادة محاولة؛ القاعدة محتفظة |
| مرفق غير مدعوم للموديل | رفض قبل الإرسال (لا حرق توكنز) |
| عزل الأخطاء | كل بطاقة حالة مستقلة؛ فشل مزود لا يلمس البقية |

## 10. الاختبارات والتحقق
- **Vitest** (منطق صرف): قاعدة التوريث الثلاثية، تجميع الاستهلاك، تسلسل Markdown، السجل، الاسترجاع من meta.json.
- مزودات وهمية (Mock) — لا نداءات حقيقية ولا توكنز في الاختبارات؛ كل اختبار **يحقن fetch مزيّفًا** في طبقة النقل بدلاً من الشبكة.
- سلسلة التحقق بإلزامية: `pnpm typecheck` → `pnpm lint` → `pnpm test` → `pnpm build` — لا ادعاء نجاح بلا تشغيل فعلي.

## 11. الأمان
- المفاتيح في IndexedDB محليًا فقط؛ تُرسل حصرًا للمزود المستدعى؛ لا تظهر في السجلات ولا تُصدَّر.
- صلاحيات Tauri بالحد الأدنى (نطاقات المزودين الأربعة + مجلد الجلسات).
- صفر تتبع خارجي. محتوى النماذج يُعامل كمدخل غير موثوق (لا تنفيذ، عرض فقط).
